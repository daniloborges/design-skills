# design-skills

Claude Code plugin `design`: three skills for semantic type styles and spacing variables, in Figma and in code. Skill text and scripts are in Portuguese; everything else is English.

## Layout

| Path | Role |
|---|---|
| `shared/` | Only place to edit rules and taxonomy. Everything under `skills/*/references/` is a generated copy. |
| `figma/*.md` | Condensed versions for the Figma in-app agent. Hand-maintained, so they go stale when `shared/` changes. |
| `tools/figma-run/` | Optional runner with its own `package.json`. Not part of the plugin. |

## How this repo works

- After editing `shared/`, run `./sync.sh` and commit the resulting `references/`. CI fails on any difference. Never edit a `references/` file directly.
- `dist/*.skill` is generated by `sync.sh` and stays out of git. The release workflow attaches it to the GitHub Release.
- Versions come from changesets. Never edit `version` in `package.json`, `.claude-plugin/plugin.json` or `.claude-plugin/marketplace.json`; `scripts/sync-versions.mjs` copies it.
- Every pull request needs a `.changeset/*.md` (`pnpm changeset`). The package manager is pnpm.
- The taxonomy is a closed list with at most one modifier per name. Adding a name needs a reason in `shared/taxonomia.md` first.
- The Figma skills change the user's file only after an explicit approval step. A new mode that writes to Figma keeps that stop and a dry-run.

## Source of truth

| What | Where |
|---|---|
| Type names, size ranges, floors | `shared/taxonomia.md` |
| Spacing scale and fit rules | `shared/espacamento.md` |
| Optional Brazilian compliance audit | `shared/legal/` |
| Lint checks and their IDs | table in `skills/tipografia-semantica-codigo/SKILL.md`, implemented in `scripts/checar-tipografia.mjs` |
| Release flow | `.github/workflows/release.yml`; human steps in `CONTRIBUTING.md` |

## Keeping this file current

Update the affected line in the same change when: a top-level folder is added or removed; a file in `figma/` or `tools/` changes role; the release or sync flow changes; a rule above stops being true.
